LVM Anki 卡片预览

共 84 个 Note，预计生成 90 张 Card。此页面仅用于查看题面、最低合格答案与必要补充，不显示来源、标签和维护信息。

01
正面

从空闲分区到应用可用目录，LVM 相关的主要层次按顺序是什么？

答案面

设备或分区 → PV → VG → LV → 文件系统 → 挂载点。

每一层解决的问题不同，不能用单一查询代替完整验收。

02
正面

LVM 中的 PV 是什么？

答案面

被 LVM 初始化并纳入管理的物理设备或分区。

pvcreate 会写入 LVM 标签和元数据。

03
正面

LVM 中的 VG 承担什么作用？

答案面

把一个或多个 PV 的容量汇聚成可分配的空间池。

LV 从 VG 分配容量，而不是直接从挂载目录分配。

04
正面

LVM 中的 LV 是什么？

答案面

从 VG 中分配出的虚拟块设备，可在其上创建文件系统或供其他上层使用。

LV 存在并不等于已经创建文件系统或挂载。

05
正面

lvs 显示 LV 已存在，能否证明应用目录已经可用？

答案面

不能。还要确认文件系统、当前挂载和持久挂载配置。

LV 只是块设备层。

06
正面

为什么 lvs 的 LV 大小与 df -hT 显示的文件系统大小可能略有不同？

答案面

因为 lvs 显示块设备标称容量，文件系统会占用元数据并以自己的方式报告可用空间。

小幅差异不等于扩容失败，应判断两层是否都发生预期变化。

07
正面

pvs、vgs、lvs 分别主要回答什么问题？

答案面

PV 属于哪个 VG；VG 有多大及剩余多少；LV 的名称、大小、路径和映射。

三组命令对应三个不同 LVM 层次。

08
正面

挂载点目录已经存在，能否证明文件系统已经挂载？

答案面

不能。目录即使未挂载也会存在，应使用 findmnt 或 mountpoint 验证。

挂载失败时把数据写进空目录，可能实际占用根文件系统。

09
正面

准备操作一块新磁盘或分区时，先用什么命令观察块设备层级、文件系统和挂载点？

答案面
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

不要仅凭设备名猜测它是否空闲。

10
正面

怎样确认 /dev/vdb1 是否已经被 LVM 当作 PV 使用？

答案面
pvs -o pv_name,vg_name,pv_size,pv_free

lsblk 不能完整替代 PV 查询。

11
正面

扩展 LV 前，应使用哪一层的查询判断真正可分配的剩余空间？

答案面

查看目标 VG 的 vg_free 或 vg_free_count。

磁盘有空闲空间不等于该空间已经进入目标 VG。

12
正面

查看 LV 名称、所属 VG、大小、设备路径和底层设备的推荐命令是什么？

答案面
lvs -o lv_name,vg_name,lv_size,lv_path,devices

优先查询 lv_path，不要仅凭记忆拼设备路径。

13
正面

怎样确认 /srv/project 当前由哪个设备提供？

答案面
findmnt /srv/project

它回答当前挂载关系，不等于持久配置一定正确。

14
正面

df -hT /srv/project 主要验证哪一层？

答案面

已挂载文件系统的类型、容量和使用情况。

它不显示 VG 剩余容量，也不能代替 vgs。

15
正面

为什么执行 pvcreate 或 mkfs 前必须重新确认设备身份？

答案面

因为它们会写入元数据或重建文件系统，作用到错误设备时可能破坏原数据。

设备名称相似时尤其不能依赖记忆。

16
正面

题目要求扩展 /srv/project，最少应先建立哪些对象之间的对应关系？

答案面

挂载点 → 文件系统 → LV → VG，并确认 VG 的剩余容量。

不要从目录名直接猜测 LV 名。

17
正面

Physical Extent（PE）是什么？

答案面

VG 中大小固定的物理容量分配单位。

PE 大小在 VG 层定义。

18
正面

普通线性 LV 中，LE 与 PE 通常是什么关系？

答案面

一个 LE 映射到一个 PE。

因此 extent 数量乘以 PE 大小可得到 LV 标称容量。

19
正面

PE 大小属于 PV、VG 还是 LV？

答案面

属于 VG。

应在 vgcreate 时设置，而不是在 lvcreate 时设置。

20
正面

VG 的 PE 大小为 16 MiB，LV 使用 50 个 extent，LV 标称容量是多少？

答案面

800 MiB。

计算为 50 × 16 MiB。

21
正面

lvcreate -L 与 lvcreate -l 的核心区别是什么？

答案面

-L 按容量分配；-l 按 extent 数量或百分比分配。

题目明确要求 PE/LE 数量时应优先用 -l。

22
正面

怎样让新 LV 使用 VG 的全部剩余 extent？

答案面
lvcreate -l 100%FREE -n <LV> <VG>

只有题目确实要求使用全部剩余空间时才这样做。

23
正面

-l 70 与 -l +20 在扩容时分别表示什么？

答案面

前者把目标总数设为 70 个 extent；后者在当前基础上增加 20 个 extent。

加号决定是目标值还是增量。

24
正面

查看 VG 的 PE 大小、总 extent 和空闲 extent 的命令是什么？

答案面
vgs <VG> -o vg_name,vg_extent_size,vg_extent_count,vg_free_count

处理按 extent 计数的题目时比只看 VFree 更直接。

25
正面

把确认空闲的 /dev/vdb1 初始化为 PV 的命令是什么？

答案面
pvcreate /dev/vdb1

执行前必须确认设备中没有需要保留的数据。

26
正面

pvcreate 对设备做了什么？

答案面

写入 LVM 标签和元数据，使设备可以加入 VG。

它不会自动创建 VG、LV 或文件系统。

27
正面

使用 /dev/vdb1 创建 PE 大小为 16 MiB 的 projectvg，命令是什么？

答案面
vgcreate -s 16M projectvg /dev/vdb1

-s 设置 VG 的 PE 大小。

28
正面

创建 PV 和 VG 后，至少用哪些命令分别验证成员关系和容量？

答案面

使用 pvs 验证 PV 所属 VG，使用 vgs 验证 VG 大小、空闲空间和 PE 大小。

两层验证不能合并成一句“命令成功”。

29
正面

PV 必须是分区吗？

答案面

不必须。PV 可以是整个块设备，也可以是分区。

应根据题目和现有磁盘布局选择，不能覆盖已有数据。

30
正面

发现 /dev/vdb1 已有文件系统或挂载点时，能否直接执行 pvcreate？

答案面

不能。必须先确认数据是否可丢弃以及设备是否选错。

不要用强制参数绕过调查。

31
正面

题目要求 VG 的 PE 大小为 16 MiB，但 VG 已经按其他 PE 大小创建。能否通过 lvcreate 修正？

答案面

不能。PE 大小是 VG 属性，lvcreate 只能从现有 VG 分配 LV。

应回到 VG 的初始状态和题目要求重新判断。

32
正面

在 projectvg 中创建 50 个 extent、名为 projectlv 的 LV，命令是什么？

答案面
lvcreate -l 50 -n projectlv projectvg

小写 -l 表示 extent 数量。

33
正面

在 projectvg 中按容量创建 800 MiB 的 projectlv，命令骨架是什么？

答案面
lvcreate -L 800M -n projectlv projectvg

题目按容量要求时使用大写 -L。

34
正面

怎样避免凭记忆猜测新 LV 的设备路径？

答案面

使用 lvs -o lv_name,vg_name,lv_path 查询 lv_path。

典型路径是 /dev/<VG>/<LV>。

35
正面

在新 LV /dev/projectvg/projectlv 上创建 XFS 的命令是什么？

答案面
mkfs.xfs /dev/projectvg/projectlv

只对确认无需保留数据的新 LV 执行。

36
正面

为什么扩展现有 XFS LV 时不能再次执行 mkfs.xfs？

答案面

因为 mkfs.xfs 会重新创建文件系统并破坏原有数据，它不是扩容命令。

扩容应使用 lvextend --resizefs 或 xfs_growfs。

37
正面

获取 LV 上文件系统 UUID 的核心命令是什么？

答案面
blkid /dev/projectvg/projectlv

也可用 lsblk -f 查看，但写入 fstab 前要复制真实 UUID。

38
正面

将 XFS 按 UUID 持久挂载到 /srv/project 的 fstab 条目骨架是什么？

答案面
UUID=<UUID> /srv/project xfs defaults 0 0

<UUID> 必须替换为当前文件系统的真实值。

39
正面

修改 /etc/fstab 后为什么执行 systemctl daemon-reload？

答案面

让 systemd 重新生成并加载由 fstab 条目对应的 mount units。

随后仍需验证并实际挂载。

40
正面

重启前检查 /etc/fstab 明显问题的命令是什么？

答案面
findmnt --verify

检查通过后仍应使用 mount -a 或挂载目标进行实际验证。

41
正面

修改 fstab 后，怎样在当前会话中尝试挂载所有尚未挂载的条目？

答案面
mount -a

出现错误时应先修正，不能直接重启碰运气。

42
正面

验证 /srv/project 当前确实挂载了目标文件系统，推荐看哪些结果？

答案面

findmnt /srv/project、df -hT /srv/project，并可结合 lsblk -f。

分别确认来源设备、文件系统类型和容量。

43
正面

/etc/fstab 一行中的前四个核心字段分别是什么？

答案面

设备标识、挂载点、文件系统类型、挂载选项。

后两个字段用于 dump 和 fsck 顺序；本章示例为 0 0。

44
正面

为什么扩大 LV 后还必须确认文件系统是否增长？

答案面

因为 LV 是底层块设备，文件系统不会因块设备变大而必然自动使用新增空间。

应分别用 lvs 和 df -hT 验证。

45
正面

在 LVM 扩容任务中，--resizefs 把哪两个动作连接起来？

答案面

扩大 LV，并随后扩大其上的受支持文件系统。

它避免只完成块设备层而遗漏文件系统层。

46
正面

给 projectlv 增加 20 个 extent，并同时扩大文件系统的推荐命令是什么？

答案面
lvextend --extents +20 --resizefs projectvg/projectlv

短选项可写为 lvextend -l +20 -r ...。

47
正面

lvextend --resizefs 中的 --resizefs 解决什么问题？

答案面

在扩大 LV 后继续调整受支持的文件系统，使新增块设备空间可被文件系统使用。

没有它时，LV 与文件系统大小可能不一致。

48
正面

只执行 lvextend 后，lvs 变大但 df 不变，最可能说明什么？

答案面

底层 LV 已扩大，但文件系统尚未扩展到新增空间。

应根据文件系统类型使用 --resizefs 或对应工具。

49
正面

已挂载的 XFS 文件系统需要单独扩容时，核心命令骨架是什么？

答案面
xfs_growfs <MOUNT_POINT>

例如 xfs_growfs /srv/project；参数是挂载点。

50
正面

为什么扩容前必须先确认文件系统类型？

答案面

因为 XFS 与 ext4 使用的文件系统扩容工具和缩容边界不同。

不能把 xfs_growfs 与 resize2fs 混用。

51
正面

扩容完成后，为什么必须同时查看 lvs 和 df -hT？

答案面

前者证明 LV 块设备容量，后者证明文件系统实际使用了新增空间。

两个结果对应不同层次。

52
正面

怎样证明扩容没有通过重新格式化或替换文件系统完成？

答案面

扩容前后检查原文件内容或校验值保持不变。

容量正确并不能单独证明数据被保留。

53
正面

PE 为 16 MiB，给 LV 增加 20 个 extent，会增加多少标称容量？

答案面

320 MiB。

计算为 20 × 16 MiB。

54
正面

-L 1120M 与 -L +320M 在 lvextend 中有何区别？

答案面

前者设置目标总大小；后者在当前基础上增加 320 MiB。

不要遗漏增量写法中的加号。

55
正面

目标 VG 的空闲 extent 不足时，第一步应做什么？

答案面

查询并确认一个可安全使用的新设备或分区。

不能通过反复执行 lvextend 获得不存在的 VG 空间。

56
正面

把空闲 /dev/vdc1 加入 projectvg 的核心命令序列是什么？

答案面
pvcreate /dev/vdc1
vgextend projectvg /dev/vdc1

先成为 PV，再进入 VG。

57
正面

能否把尚未属于 VG 的 /dev/vdc1 直接交给 lvextend 扩大 LV？

答案面

不能。设备要先初始化为 PV，再通过 vgextend 加入目标 VG。

LV 只能从所属 VG 的可用 extent 获得空间。

58
正面

vgextend 后应重点验证什么？

答案面

新 PV 已属于目标 VG，VG 总容量和空闲 extent 已增加。

使用 pvs 和 vgs 分别验证成员关系与容量。

59
正面

发现候选新设备已经属于其他 VG 时，应怎样处理？

答案面

停止初始化，确认设备用途并重新选择可用设备。

不要用强制参数覆盖已有 LVM 元数据。

60
正面

RHEL 9 中，XFS 文件系统能否原地缩小？

答案面

不能。XFS 支持增长，但不支持缩小。

需要更小容量时通常要新建文件系统并迁移数据。

61
正面

为什么不能把 lvreduce 当作 lvextend 的简单反向命令？

答案面

减少 LV 可能截断仍被文件系统使用的数据块，必须先满足文件系统安全缩容条件。

对 XFS 不存在原地缩容路径。

62
正面

遇到 LVM 配置异常时，是否应通过 lvremove、vgremove 或 pvremove 重新开始？

答案面

不应。除非题目明确要求且已证明没有需要保留的数据。

这些都是破坏性清理命令，不是通用排错手段。

63
正面

完成 LVM 创建任务时，稳定的证据推进顺序是什么？

答案面

确认设备 → 确认 PV/VG/LV 现状 → 创建或调整 LVM → 创建/扩展文件系统 → 配置挂载 → 分层验证。

不是在所有环境中无条件执行同一串写命令。

64
正面

看到 lvs 中 LV 已扩大，但业务仍提示磁盘空间不足，下一步优先检查什么？

答案面

检查目标挂载点对应的文件系统是否已经扩大，并确认业务实际写入的是该挂载点。

重点查看 df -hT 和 findmnt。

65
正面

经典任务中，最终验收为什么要同时检查 PV、VG、LV、文件系统和挂载点？

答案面

因为它们是独立层次，任一局部正确都不能证明完整目标已达到。

还要验证数据保留和持久挂载。

66
正面

projectvg 的 PE 为 16 MiB，projectlv 最终为 70 个 extent，其标称容量是多少？

答案面

1120 MiB。

初始 50 个 extent，再增加 20 个。

67
正面

怎样验证 /etc/fstab 中的 UUID 没有写错？

答案面

比较 fstab 条目与 blkid/lsblk -f 的真实 UUID，并运行 findmnt --verify 与挂载测试。

不能复制讲义中的占位 UUID。

68
正面

怎样证明 /srv/project 当前确实由 projectlv 提供，而不是根文件系统中的普通目录？

答案面

使用 findmnt /srv/project 查看挂载源，并结合 df -hT /srv/project。

目录存在本身没有证明力。

69
正面

扩展任务中 vg_free_count 小于 20，下一步应怎样推进？

答案面

确认 /dev/vdc1 空闲后执行 pvcreate 和 vgextend，再重新验证 VG 余量。

随后才执行 LV 与文件系统扩容。

70
正面

经典任务中，标记文件在扩容前后保持相同能证明什么？

答案面

证明扩容没有通过重新格式化或替换文件系统来获得结果。

它是数据保留的直接证据之一。

71
正面

从两个空闲分区完成经典任务的主要流程骨架是什么？

答案面

调查设备 → 创建 PV/VG → 创建 LV → 建 XFS → 按 UUID 持久挂载 → 写入数据 → 必要时扩展 VG → 扩展 LV/文件系统 → 综合验证。

每一步都应由前一层查询结果支撑。

72
正面

经典任务完成后，仅 mount -a 没有报错是否足以证明全部目标完成？

答案面

不足。还要检查挂载源、LV 和文件系统容量、PE 要求、数据内容与 UUID 一致性。

无报错只是持久挂载验证的一部分。

73
正面

/dev/projectvg/projectlv 与 /dev/mapper/projectvg-projectlv 通常是什么关系？

答案面

它们通常指向同一个 LV 设备。

优先使用 lvs 查询出的 lv_path，避免手工处理 mapper 名称转义。

74
正面

为什么“磁盘还有未分区空间”不能直接证明目标 VG 可以扩容？

答案面

因为未分区空间尚未成为 PV，也没有加入目标 VG。

需要完成设备/分区、PV、VG 三层转换。

75
正面

如何在本机快速查找 lvextend 的 extent 和文件系统扩容选项？

答案面
man lvextend
lvextend --help

考试环境中应能使用本地帮助确认低频细节。

76
正面

怎样查询哪个软件包提供一个缺失的命令，例如 pvcreate？

答案面
dnf provides '*/pvcreate'

只需掌握通用反查方法，不必背完整软件包表。

77
正面

LVM 的核心层次是设备/分区 → [...] → [...] → LV → 文件系统 → 挂载点。

答案面

LVM 的核心层次是设备/分区 → PV → VG → LV → 文件系统 → 挂载点。

PV 进入 VG，LV 再从 VG 分配容量。

78
正面

PE 大小属于 [...]；创建 LV 时，小写 -l 按 [...] 分配。

答案面

PE 大小属于 VG；创建 LV 时，小写 -l 按 extent 数量或百分比 分配。

不要把 PE 大小写到 lvcreate。

79
正面

vgcreate [...] projectvg /dev/vdb1 创建 PE 大小为 16 MiB 的 VG。

答案面

vgcreate -s 16M projectvg /dev/vdb1 创建 PE 大小为 16 MiB 的 VG。

-s 是 physical extent size。

80
正面

lvcreate [...] -n projectlv projectvg 创建 50 个 extent 的 LV。

答案面

lvcreate -l 50 -n projectlv projectvg 创建 50 个 extent 的 LV。

按容量创建则使用大写 -L。

81
正面

持久挂载的 fstab 核心结构是 [...] [...]。

答案面

持久挂载的 fstab 核心结构是 UUID=<UUID> /srv/project xfs defaults 0 0。

UUID 必须来自当前文件系统。

82
正面

lvextend --extents [...] [...] projectvg/projectlv 同时增加 20 个 extent 并扩展文件系统。

答案面

lvextend --extents +20 --resizefs projectvg/projectlv 同时增加 20 个 extent 并扩展文件系统。

加号表示增量。

新设备要成为现有 LV 的可用空间，先 [...]，再 [...]。

答案面

答案面

RHEL 9 中，XFS 支持增长，但不支持缩小。
