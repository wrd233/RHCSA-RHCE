正面

Playbook 顶层 YAML 类型是什么？

背面

play 的列表（sequence）。

每个 play 是 mapping。

正面

一个 task 通常应调用几个模块？

背面

一个。

name/when/register 等是 task 关键字。

正面

为什么 mode 常写 '0644'？

背面

避免 YAML 数值类型歧义并保留权限表达。

模块接收明确模式。

正面

查询模块字段和示例用什么？

背面

ansible-doc <FQCN>

以当前安装版本为准。

正面

syntax-check 证明什么？

背面

控制端能解析 Playbook 和静态结构。

不证明连接或远端成功。

正面

执行前查看目标主机用什么？

背面

ansible-playbook play.yml --list-hosts

避免错误范围。

正面

限制第一轮到 servera 用什么？

背面

--limit servera

成功后再扩展。

正面

command 与 shell 的关键区别是什么？

背面

command 不经 Shell；shell 解释管道、重定向等。

优先专用模块。

正面

为什么包安装优先 dnf 模块而不是 command？

背面

模块表达 state 并能幂等判断。

command 通常每次执行。

正面

recap 无 failed 能否证明 HTTP 正确？

背面

不能；还要远端服务/监听和协议验证。

执行结果不等于功能。

正面

第二次仍 changed 的调查方向是什么？

背面

定位具体 task 的动态输入、无条件命令或 changed_when。

先解释再接受。

正面

unsupported parameters 下一步是什么？

背面

核对 FQCN 和 ansible-doc 当前字段。

不猜参数。

正面

YAML 报错行一定是根因行吗？

背面

不一定；上一层缩进或未闭合结构可导致后续报错。

向上检查。

正面

Playbook 完整验收链是什么？

背面

syntax/list → limit → 远端终态 → 全量 → 第二次执行 → 再验收。

幂等与正确性都要。

正面

Playbook 静态门：[…]、[…]、--list-tasks。

背面

Playbook 静态门：--syntax-check、--list-hosts、--list-tasks。

再 limit 执行。

正面

服务当前状态用 state: […]，启动持久状态用 enabled: […]。

背面

服务当前状态用 state: started，启动持久状态用 enabled: true。

两维度。
