正面

查看 PID、PPID、用户、状态、nice 和完整命令的骨架是什么？

背面

ps -eo pid,ppid,user,stat,ni,cmd

可按判断需要增加 --sort 字段。

正面

按用户和进程名查 PID 与命令行，推荐什么？

背面

pgrep -a -u <USER> <NAME>

操作前仍要核对完整命令行。

正面

kill <PID> 默认发送哪个信号？

背面

SIGTERM（15）。

它请求程序有序退出。

正面

为什么 SIGKILL 不应作为终止进程的第一选择？

背面

程序无法捕获它或清理资源，可能留下不一致状态。

先 TERM、验证，再在确认对象后 KILL。

正面

僵尸进程为什么不能靠继续发送信号清除？

背面

它已经退出，只等待父进程回收状态。

应调查父进程。

正面

nice 值越大，CPU 调度优先级怎样变化？

背面

越低。

nice 不是 CPU 配额或完成时间保证。

正面

jobs、fg、bg 的作用范围是什么？

背面

当前 Shell 的作业表。

不适合作为长期服务管理方案。

正面

systemctl start 与 enable 的核心区别是什么？

背面

start 改变当前运行；enable 建立开机启动依赖。

enable --now 同时处理两者。

正面

同时启用并立即启动 httpd 的命令是什么？

背面

systemctl enable --now httpd

后续分别验证 active 和 enabled。

正面

systemctl mask 比 disable 多做了什么？

背面

阻止 unit 被手工或依赖启动，通常链接到 /dev/null。

解除使用 unmask。

正面

什么时候需要 systemctl daemon-reload？

背面

unit 文件或 drop-in 发生变化时。

它不自动重启应用服务。

正面

应用配置文件改变后，daemon-reload 能否让应用读取新配置？

背面

不能；应先做应用语法检查，再 reload 或 restart 应用。

unit 定义与应用配置是不同对象。

正面

查看 unit 主文件与 drop-in 合并来源，使用什么？

背面

systemctl cat <UNIT>

属性查询可用 systemctl show -p。

正面

服务 active 能否证明端口与业务访问正确？

背面

不能；还要检查监听、过滤层和最终功能。

active 只描述 systemd 当前状态。

正面

查看当前启动中 httpd 最近 10 分钟日志的骨架是什么？

背面

journalctl -u httpd -b --since '-10 min'

--no-pager 适合非交互输出。

正面

journalctl -b -1 查询什么？

背面

上一次启动轮次的日志。

是否可见取决于 journal 持久存储。

正面

当前能看到 journal，能否证明重启后仍能看到？

背面

不能；当前日志可能只在 /run/log/journal 易失存储中。

持久存储通常涉及 /var/log/journal 与 Storage 配置。

正面

校验 rsyslog 配置语法的命令是什么？

背面

rsyslogd -N1

通过后再重启服务并发送测试消息。

正面

生成带 facility/priority 与 tag 的受控日志消息，使用什么骨架？

背面

logger -p local0.notice -t exam-check 'message'

再分别查询 journal 和目标文件。

正面

日志时间范围查询为空时，为什么先检查 timedatectl？

背面

错误时区或时钟会让预期事件落在另一时间范围。

空日志不一定表示事件未发生。

正面

修改时区与配置网络时间同步是同一状态吗？

背面

不是；时区控制显示偏移，时间同步控制时钟来源与校正。

两者分别验证。

正面

查看 chrony 时间源和跟踪状态分别用什么？

背面

chronyc sources -v 与 chronyc tracking。

服务 active 不能替代这两层。

正面

chrony sources 中 ^*、^+、^? 的常见含义是什么？

背面

当前选中；可接受候选；不可达或无有效测量。

结合完整输出与 tracking 判断。

正面

用户 crontab 的五个时间字段顺序是什么？

背面

分、时、日、月、星期。

后面直接是命令。

正面

/etc/crontab 或 /etc/cron.d/ 比用户 crontab 多哪个字段？

背面

时间字段后多一个执行用户字段。

两种格式混用会让任务错误。

正面

每天 02:15 运行脚本的用户 crontab 时间表达是什么？

背面

15 2 * * *

后接绝对脚本路径与重定向。

正面

为什么 cron 中应使用绝对路径并显式重定向？

背面

cron 的 PATH、工作目录和环境有限，且无人交互读取输出。

让脚本明确依赖而非复制完整交互环境。

正面

提交、列出、查看、删除 at 作业分别用什么？

背面

at、atq、at -c <JOB>、atrm <JOB>。

还要确认 atd 和真实产物。

正面

cron 配置存在能否证明任务执行成功？

背面

不能；还要检查 crond、目标身份环境、日志和实际产物。

手工执行成功也不能证明 cron 环境成功。

正面

服务启动失败的推荐证据顺序是什么？

背面

status → 当前 boot 的 unit journal → 应用语法 → 端口/权限/SELinux。

不要反复 restart 覆盖最近证据。

正面

手工运行脚本成功而 cron 失败，优先比较什么？

背面

执行用户、PATH、工作目录、环境变量、权限和错误输出。

可在精简环境中复现。

正面

unit 为 enabled 但没有运行，下一步查什么？

背面

is-active、status、本次启动 journal，以及是否 masked/条件跳过。

enabled 只表示启动依赖。

正面

服务、日志、时间、cron 综合任务的验收骨架是什么？

背面

服务语法/状态/功能 → 日志语法/受控消息 → 时区/源/tracking → cron 配置/身份/产物。

每组状态分别证明。

正面

systemctl […] httpd 同时建立[…]。

背面

systemctl enable --now httpd 同时建立启动依赖并立即启动。

后续分别查 active 与 enabled。

正面

用户 cron 字段顺序：[…]；系统 cron 随后还要写[…]。

背面

用户 cron 字段顺序：分 时 日 月 星期；系统 cron 随后还要写执行用户。

最后才是命令。

正面

chrony 验收：[…] 看源，[…] 看时钟跟踪。

背面

chrony 验收：chronyc sources -v 看源，chronyc tracking 看时钟跟踪。

active 不等于已同步。
