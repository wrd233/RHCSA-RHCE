网络文件系统与自动挂载 - Anki 预览

正面

查询 NFS 导出列表的常用命令是什么？

背面

showmount -e <SERVER>

NFSv4 环境仍需结合服务端设计。

正面

查看某目录当前 NFS 挂载源，使用什么？

背面

findmnt <MOUNT_POINT>

目录存在不代表已挂载。

正面

root_squash 的核心效果是什么？

背面

把客户端 root 映射为服务端匿名身份。

不应为写入失败默认关闭。

正面

持久 NFS fstab 的设备字段骨架是什么？

背面

<SERVER>:/<EXPORT>

类型通常为 nfs。

正面

NFS fstab 中 _netdev 表达什么？

背面

该挂载依赖网络可用。

不保证服务器一定可达。

正面

怎样证明 NFS fstab 条目真实生效？

背面

卸载当前挂载后运行 mount -a，再用 findmnt 核对。

另做读写测试。

正面

autofs master map 的职责是什么？

背面

把挂载基目录或 direct map 标记关联到子 map。

子 map 定义 key 与远端源。

正面

展开 autofs 有效映射的命令是什么？

背面

automount -m

用于发现 map 解析错误。

正面

indirect map 中 key docs 挂在 /shares 下，最终路径是什么？

背面

/shares/docs

访问该路径触发挂载。

正面

autofs 触发前 findmnt /shares/docs 无结果是否一定失败？

背面

不一定；按需挂载可能尚未触发。

先访问 key 再查询。

正面

autofs wildcard map 中 * 与 & 常怎样配合？

背面

* 捕获访问 key，& 在远端位置代入该 key。

适合用户目录映射。

正面

NFS 报 access denied by server 时，客户端 chmod 能修复吗？

背面

通常不能；应核对导出路径、来源和服务端权限。

问题在服务端策略层。

正面

NFS 当前挂载成功能否证明重启后保持？

背面

不能；还要验证 fstab 或 autofs 持久配置。

生命周期不同。

正面

查看 NFS 实际挂载版本和选项，使用什么？

背面

nfsstat -m

与 findmnt 交叉检查。

正面

修改 autofs map 后的推荐验证链是什么？

背面

automount -m → reload autofs → 访问 key → findmnt → journal。

不要只看服务 active。

正面

持久 NFS 与 autofs 的核心区别是什么？

背面

前者常驻/启动挂载；后者访问时按需挂载并可超时卸载。

按题意选择。

正面

挂载到非空目录时原内容发生什么？

背面

被挂载文件系统暂时遮蔽，卸载后重新可见。

不是被删除。

正面

NFS 综合任务的最小验收层次是什么？

背面

解析/路由 → 导出 → 挂载源 → 持久或触发 → 目标身份功能。

每层独立取证。
