正面

从空闲设备到应用可用目录，完整层级顺序是什么？

背面

设备/分区 → PV → VG → LV → 文件系统 → 挂载点。

用于定位命令作用层，不要求背长定义。

正面

pvs、vgs、lvs 分别读取哪一层？

背面

分别读取 PV、VG、LV 元数据。

文件系统与挂载状态要用 df、findmnt 等命令。

正面

LVM 查询命令中的 -o 用来做什么？

背面

指定输出字段。

例如 vgs -o vg_name,vg_free,vg_free_count。

正面

lvs 显示 LV 存在，是否足以证明目录可用？

背面

不足。还要确认文件系统、当前挂载和持久挂载。

LV 只属于块设备层。

正面

lvs 变大而 df -hT 不变，优先判断哪一层未完成？

背面

文件系统层未扩展。

先确认文件系统类型，再使用对应扩容工具。

正面

目录存在但 findmnt <目录> 没有结果，说明什么？

背面

该目录当前没有作为挂载点生效。

继续写入可能实际占用根文件系统。

正面

查看块设备、文件系统类型和挂载点的高频命令是什么？

背面
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

先确认设备身份，再执行写操作。

正面

查看 PV 名称、所属 VG、大小和空闲容量的命令是什么？

背面
pvs -o pv_name,vg_name,pv_size,pv_free

用于确认候选设备是否已经属于某个 VG。

正面

查看 VG 的 PE 大小和空闲 extent 数量，推荐什么命令？

背面
vgs <VG> -o vg_name,vg_free,vg_extent_size,vg_free_count

extent 题优先看 vg_free_count。

正面

查看 LV 路径与底层设备映射，推荐什么命令？

背面
lvs <VG/LV> -o lv_name,vg_name,lv_size,lv_path,devices

优先查询 lv_path，不要凭记忆拼路径。

正面

确认 /srv/project 当前挂载源的命令是什么？

背面
findmnt /srv/project

它验证当前挂载，不证明 fstab 一定正确。

正面

查看 /srv/project 文件系统类型、容量与使用率的命令是什么？

背面
df -hT /srv/project

-h 可读单位，-T 显示文件系统类型。

正面

只检查一个目录是否为挂载点，可使用什么命令？

背面
mountpoint /srv/project

需要知道挂载源时仍优先用 findmnt。

正面

PE 大小属于 PV、VG 还是 LV？

背面

VG。

通过 vgcreate -s 设置。

正面

VG 的 PE 为 16 MiB，50 个 extent 对应多少标称容量？

背面

800 MiB。

50 × 16 MiB。

正面

lvcreate -l 与 lvcreate -L 的区别是什么？

背面

-l 按 extent 数量/百分比；-L 按容量。

小写 l 与大写 L 不能混淆。

正面

在扩容命令中，-l 70 与 -l +20 分别是什么语义？

背面

前者把目标总量设为 70 PE；后者在当前基础上增加 20 PE。

加号表示增量。

正面

让新 LV 使用 VG 的全部剩余 extent，典型参数是什么？

背面
-l 100%FREE

只在题目明确要求使用全部剩余空间时使用。

正面

让现有 LV 增加 VG 的全部剩余 extent，典型参数是什么？

背面
-l +100%FREE

+ 表示在现有大小上增加。

正面

vgcreate -s 16M 中的 -s 表示什么？

背面

设置 VG 的 PE 大小为 16 MiB。

不是设置 VG 总大小。

正面

把确认空闲的 /dev/vdb1 初始化为 PV，命令是什么？

背面
pvcreate /dev/vdb1

会写入 LVM 元数据。

正面

用 /dev/vdb1 创建 PE 为 16 MiB 的 projectvg，命令是什么？

背面
vgcreate -s 16M projectvg /dev/vdb1

参数顺序：选项、VG 名、PV。

正面

在 projectvg 中创建 50 个 extent 的 projectlv，命令是什么？

背面
lvcreate -l 50 -n projectlv projectvg

-l 是 extent，-n 是 LV 名。

正面

在 projectvg 中创建 800 MiB 的 projectlv，命令是什么？

背面
lvcreate -L 800M -n projectlv projectvg

容量题用大写 -L。

正面

lvcreate -n projectlv ... 中的 -n 表示什么？

背面

指定 LV 名称。

VG 名通常放在命令最后。

正面

怎样查询新 LV 的真实设备路径？

背面
lvs projectvg/projectlv -o lv_path

典型结果是 /dev/projectvg/projectlv。

正面

pvcreate 会自动创建 VG 或 LV 吗？

背面

不会。

需要继续执行 vgcreate 和 lvcreate。

正面

发现 /dev/vdb1 已有文件系统或挂载点，应继续 pvcreate 吗？

背面

不应。先停止并核对设备用途。

不要用强制参数覆盖证据。

正面

VG 已按错误 PE 创建，能否通过 lvcreate 修正 PE？

背面

不能。

PE 是 VG 属性。

正面

创建 PV、VG、LV 后，最小验证组合是什么？

背面

分别运行 pvs、vgs、lvs。

重点核对 PV 归属、PE/余量、LV 路径与容量。

正面

在 /dev/projectvg/projectlv 上新建 XFS，命令是什么？

背面
mkfs.xfs /dev/projectvg/projectlv

仅对无需保留数据的新 LV 使用。

正面

创建挂载点 /srv/project，命令是什么？

背面
mkdir -p /srv/project

目录存在仍不代表已经挂载。

正面

读取 LV 上文件系统 UUID，命令是什么？

背面
blkid /dev/projectvg/projectlv

也可用 lsblk -f 交叉检查。

正面

按 UUID 持久挂载 XFS 到 /srv/project 的 fstab 骨架是什么？

背面
UUID=<UUID> /srv/project xfs defaults 0 0

UUID 必须替换为本机真实值。

正面

/etc/fstab 前四个核心字段是什么？

背面

设备标识、挂载点、文件系统类型、挂载选项。

最后两个字段常见为 0 0。

正面

修改 fstab 后，为什么执行 systemctl daemon-reload？

背面

重新加载由 fstab 生成的 mount units。

仍需继续验证和实际挂载。

正面

重启前检查 fstab 明显问题的命令是什么？

背面
findmnt --verify

它不能替代实际挂载测试。

正面

在当前会话中尝试挂载所有尚未挂载的 fstab 条目，命令是什么？

背面
mount -a

报错时先修复，不要直接重启。

正面

怎样证明 /srv/project 当前由目标 LV 提供？

背面
findmnt /srv/project

同时可用 df -hT 验证类型与容量。

正面

为什么扩容现有 XFS 时不能再次执行 mkfs.xfs？

背面

因为它会重新创建文件系统并破坏数据。

扩容使用 lvextend -r 或 xfs_growfs。

正面

使用 UUID 挂载相对 /dev/vdX 路径的主要价值是什么？

背面

不依赖可能变化的设备枚举顺序。

UUID 必须来自目标文件系统。

正面

findmnt --verify 通过且 mount -a 无报错，是否足以证明整道 LVM 题完成？

背面

不足。还要核对 PV/VG/LV、文件系统容量、挂载源和题目参数。

挂载只是一层。

正面

lvextend --extents +20 中的 --extents 等价短选项是什么？

背面

-l。

小写 l。

正面

lvextend --size +320M 中的 --size 等价短选项是什么？

背面

-L。

大写 L。

正面

lvextend --resizefs 的短选项是什么？

背面

-r。

同步扩展受支持的文件系统。

正面

给 projectlv 增加 20 PE 并同步扩展文件系统，命令是什么？

背面
lvextend -l +20 -r projectvg/projectlv

长选项写法也正确。

正面

给 projectlv 增加 320 MiB 并同步扩展文件系统，命令是什么？

背面
lvextend -L +320M -r projectvg/projectlv

+ 表示增量。

正面

让 LV 使用 VG 全部剩余空间并扩展文件系统，命令骨架是什么？

背面
lvextend -l +100%FREE -r <VG/LV>

会消耗全部空闲 extent。

正面

已单独扩大 LV，扩展已挂载 XFS 的命令骨架是什么？

背面
xfs_growfs <MOUNT_POINT>

参数是挂载点，例如 /srv/project。

正面

XFS 文件系统能否原地缩小？

背面

不能。

XFS 支持增长，不支持缩小。

正面

为什么不能先执行 lvreduce 再处理 XFS？

背面

会截断文件系统仍在使用的块，导致数据损坏。

XFS 没有原地缩容路径。

正面

扩容前确认 VG 是否至少还有 20 个空闲 PE，应看哪个字段？

背面

vg_free_count。

使用 vgs ... -o vg_free_count。

正面

扩容前确认挂载点对应哪个 LV，首选什么命令？

背面
findmnt /srv/project

不要从目录名猜 LV 名。

正面

为了验证扩容保留数据，扩容前后可使用什么轻量证据？

背面

对标记文件计算并比较 sha256sum。

容量正确不能单独证明数据保留。

正面

扩容后至少用哪两条命令证明 LV 和文件系统都增长？

背面

lvs <VG/LV> 与 df -hT <MOUNT_POINT>。

分别验证块设备层与文件系统层。

正面

扩容后为什么还要运行 findmnt <MOUNT_POINT>？

背面

确认目录仍挂载到目标文件系统。

防止数据落入未挂载的普通目录。

正面

VG 空间不足时，把 /dev/vdc1 加入 projectvg 的命令序列是什么？

背面
pvcreate /dev/vdc1
vgextend projectvg /dev/vdc1

先 PV，后加入 VG。

正面

vgextend 的典型参数顺序是什么？

背面

vgextend <VG> <PV>。

目标 VG 在前，新 PV 在后。

正面

能否把尚未加入 VG 的新设备直接交给 lvextend？

背面

不能。

LV 只能使用所属 VG 的空闲 extent。

正面

vgextend 后，如何验证新设备已进入目标 VG？

背面

用 pvs 看 PV 归属，再用 vgs 看 VG 总量和空闲 PE。

两层都要确认。

正面

候选设备已经属于其他 VG，应使用强制参数重建吗？

背面

不应。

停止并核对设备用途。

正面

症状：lvextend 报 insufficient free space。第一条查询应指向哪一层？

背面

VG 层：查询 vg_free/vg_free_count。

不要继续重复扩容。

正面

症状：mount -a 报 UUID 不存在。优先核对什么？

背面

用 blkid/lsblk -f 核对 fstab 中的 UUID。

不要重建文件系统来获得新 UUID。

正面

症状：/srv/project 有数据，但 findmnt 无结果。最可能的数据落在哪里？

背面

根文件系统中的普通目录 /srv/project。

先停止写入并恢复正确挂载。

正面

症状：lvs 为 1120 MiB，df 仍约 800 MiB。下一步是什么？

背面

扩展文件系统；XFS 可运行 xfs_growfs <挂载点>。

先确认文件系统类型。

正面

lvremove、vgremove、pvremove 应当被视为什么类型的操作？

背面

破坏性删除操作。

不是通用排错手段。

正面

只看到 pvcreate、vgcreate、lvcreate 都成功，仍缺少哪些关键状态？

背面

文件系统、当前挂载、持久挂载与最终数据状态。

创建 LVM 对象不等于任务闭环。

正面

一项 LVM 任务的最小分层验收顺序是什么？

背面

pvs/vgs/lvs → findmnt/df → fstab 验证 → 数据检查。

先验收容量对象，再验收文件系统与持久关系。

正面

任务：PE 为 16 MiB，创建 50 PE 的 projectlv。核心命令是什么？

背面
lvcreate -l 50 -n projectlv projectvg

标称容量为 800 MiB。

正面

任务：PE 为 8 MiB，创建 32 PE 的 datalv。标称容量是多少？

背面

256 MiB。

32 × 8 MiB。

正面

任务：把 projectlv 从 50 PE 增加到 70 PE，并同步扩展文件系统。命令是什么？

背面
lvextend -l +20 -r projectvg/projectlv

也可使用 -l 70 -r 表达目标总量。

正面

任务：给 datalv 增加 1 GiB 并同步扩展文件系统。命令骨架是什么？

背面
lvextend -L +1G -r <VG/LV>

按容量增量使用大写 -L 和 +。

正面

任务：新建 LV 使用 VG 全部剩余空间。命令骨架是什么？

背面
lvcreate -l 100%FREE -n <LV> <VG>

新建时不加 +。

正面

任务：现有 LV 使用 VG 全部剩余空间并扩展文件系统。命令骨架是什么？

背面
lvextend -l +100%FREE -r <VG/LV>

扩展现有 LV 时带 +。

正面

任务：从挂载点 /data 找到源设备，再确认所属 VG，使用哪两步？

背面

先 findmnt /data，再用 lvs -o lv_name,vg_name,lv_path 查询 LV。

先建立挂载点到 LV 的映射。

正面

任务：创建并持久挂载新 LVM 文件系统，流程骨架是什么？

背面

调查设备 → PV → VG → LV → mkfs → UUID/fstab → verify/mount → 分层验收。

每一步都应有对应查询。

正面

任务：VG 空闲 PE 不足，新增设备扩容的流程骨架是什么？

背面

确认设备空闲 → pvcreate → vgextend → 验证 VG 余量 → lvextend -r。

新设备不能跳过 PV/VG。

正面

任务最终为 70 PE、PE 为 16 MiB，标称容量是多少？

背面

1120 MiB。

70 × 16 MiB。

正面

查看 lvextend 的本地手册和短帮助，分别用什么命令？

背面
man lvextend
lvextend --help

低频参数优先现场查询。

正面

pvdisplay、vgdisplay、lvdisplay 与 pvs/vgs/lvs 的常见区别是什么？

背面

前者偏详细单对象信息，后者偏紧凑表格查询。

考试中表格查询通常更适合快速核对。

正面

怎样快速查看所有 LV 及其底层设备映射？

背面
lvs -a -o +devices

+devices 在默认列后追加设备映射。

正面

怎样查询缺失命令（如 pvcreate）由哪个软件包提供？

背面
dnf provides '*/pvcreate'

掌握反查入口，不必背软件包表。

正面

LVM 的查询命令是 […] / […] / […]，分别对应 PV / VG / LV。

背面

LVM 的查询命令是 pvs / vgs / lvs，分别对应 PV / VG / LV。

同一编号作为一组命令回忆。

正面

vgcreate […] projectvg /dev/vdb1 中，-s 设置 VG 的 […]。

背面

vgcreate -s 16M projectvg /dev/vdb1 中，-s 设置 VG 的 PE 大小。

PE 属于 VG。

正面

lvcreate […] […] projectvg 按 50 PE 创建并命名 LV。

背面

lvcreate -l 50 -n projectlv projectvg 按 50 PE 创建并命名 LV。

小写 -l 按 extent。

正面

lvcreate […] -n projectlv projectvg 按 […] 创建 LV。

背面

lvcreate -L 800M -n projectlv projectvg 按 容量 创建 LV。

大写 -L。

正面

fstab 核心条目：[…] […]。

背面

fstab 核心条目：UUID=<UUID> /srv/project xfs defaults 0 0。

UUID 必须来自目标文件系统。

正面

修改 fstab 后，先 […]，再用 […] 实际验证。

背面

修改 fstab 后，先 findmnt --verify，再用 mount -a 实际验证。

两步职责不同。

正面

lvextend -l […] […] projectvg/projectlv 增加 20 PE 并同步扩展文件系统。

背面

lvextend -l +20 -r projectvg/projectlv 增加 20 PE 并同步扩展文件系统。

+ 是增量，-r 是 resizefs。

正面

新设备扩展现有 VG：先 […]，再 […]。

背面

新设备扩展现有 VG：先 pvcreate，再 vgextend。

不能直接交给 lvextend。

正面

XFS 支持[…]，但不支持[…]。

背面

XFS 支持增长，但不支持原地缩小。

不要对 XFS 盲目 lvreduce。

正面

新建 LV 使用全部剩余 PE：-l […]；扩展现有 LV 使用全部剩余 PE：-l […]。

背面

新建 LV 使用全部剩余 PE：-l 100%FREE；扩展现有 LV 使用全部剩余 PE：-l +100%FREE。

差异在加号。
