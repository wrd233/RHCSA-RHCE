正面

RPM 与 DNF 的核心职责区别是什么？

背面

RPM 管已安装包和本地包操作；DNF 使用仓库解析依赖并执行事务。

DNF 最终仍调用 RPM 层安装。

正面

查询本机是否已安装 httpd，使用什么？

背面

rpm -q httpd

仓库可用包查询属于 DNF 范围。

正面

列出已安装包 httpd 的文件，使用什么？

背面

rpm -ql httpd

未安装包可用 dnf repoquery -l。

正面

从现有路径 /usr/sbin/httpd 反查所属已安装包，使用什么？

背面

rpm -qf /usr/sbin/httpd

文件不存在时改用 dnf provides 查仓库。

正面

rpm -V <PACKAGE> 无输出通常说明什么？

背面

可验证的已安装文件属性与包元数据没有差异。

有输出是调查线索，不等于恶意修改。

正面

安装本地 RPM 且需要仓库解析依赖，推荐什么骨架？

背面

dnf install ./package.rpm

不使用 rpm --nodeps 绕过依赖。

正面

repo 文件位于哪个目录？

背面

/etc/yum.repos.d/*.repo

每个 section ID 应唯一。

正面

repo 的 baseurl、enabled、gpgcheck、gpgkey 分别表达什么？

背面

仓库根位置、启用状态、包签名校验、可信公钥入口。

baseurl 应指向包含 repodata 的根。

正面

dnf repolist --all 能证明什么，不能证明什么？

背面

能证明配置被解析和启用状态；不能充分证明远端元数据可达。

真实刷新用 makecache --refresh。

正面

强制刷新启用仓库元数据的命令是什么？

背面

dnf makecache --refresh

它会暴露 URL、网络和 repodata 错误。

正面

限定从 exam-baseos 查询 bash 包，命令骨架是什么？

背面

dnf repoquery --repo exam-baseos bash

证明目标仓库提供该包。

正面

GPG 校验失败时，为什么不能直接设置 gpgcheck=0？

背面

这会移除题目要求的签名安全属性，而不是修复 key、时间或来源。

先核对可信 key 和包来源。

正面

从命令名 semanage 反查提供包，使用什么？

背面

dnf provides '*/semanage'

模式应引用以防 Shell 展开。

正面

dnf install 返回成功后，最少还要验证哪些包层对象？

背面

RPM 安装记录、关键文件归属、配置和 systemd unit。

再继续验证服务状态与功能。

正面

为什么执行 dnf remove 前必须阅读 Transaction Summary？

背面

事务可能连带删除不再需要的依赖或影响其他软件。

不以包名猜实际影响集合。

正面

查看 DNF 事务列表和指定事务详情分别用什么？

背面

dnf history 与 dnf history info <ID>。

undo 仍受当前仓库版本可用性约束。

正面

为什么 DNF 事务成功不能证明 Web 服务题完成？

背面

事务只证明包层；还需配置、active/enabled、监听和访问。

包安装不会自动保证服务终态。

正面

查看 AppStream 模块流与模块详情分别用什么？

背面

dnf module list 与 dnf module info <MODULE>。

可用流由当前 RHEL 9 仓库决定。

正面

dnf module reset 会自动删除该模块已安装包吗？

背面

不会；它重置流选择，不等于卸载内容。

改流前检查已安装状态和依赖影响。

正面

查询和安装软件包组的骨架是什么？

背面

dnf group list/info 与 dnf group install '<GROUP>'。

安装组后仍要验证各目标服务。

正面

设置静态主机名的命令是什么？

背面

hostnamectl set-hostname <FQDN>

不会自动创建 DNS 或 hosts 记录。

正面

验证主机名本身与名称解析分别用什么？

背面

hostnamectl status 与 getent hosts <FQDN>。

两个对象独立。

正面

systemctl isolate 与 set-default 的核心区别是什么？

背面

isolate 当前切换 target；set-default 设置下次启动默认 target。

isolate 可能停止当前服务或会话。

正面

查看 tuned 推荐 profile 与当前 profile 分别用什么？

背面

tuned-adm recommend 与 tuned-adm active。

推荐值不等于已应用值。

正面

下载 repodata/repomd.xml 返回 404，优先检查什么？

背面

baseurl 是否指向包含 repodata 的仓库根，以及变量展开。

清缓存不会修复错误 URL。

正面

DNF 报依赖冲突或包被过滤，下一步证据是什么？

背面

完整错误、repoquery 依赖/反向依赖、仓库和 module 状态。

不先使用 --allowerasing。

正面

为什么 --allowerasing 不是依赖冲突的第一尝试？

背面

它可能删除冲突包并影响其他任务，必须先理解事务摘要。

先定位仓库、架构、版本流或依赖缺口。

正面

指定仓库安装服务的完整验收骨架是什么？

背面

repo 解析/刷新 → 来源查询 → DNF 事务 → RPM/文件/unit → 配置语法 → 服务状态/功能。

每层使用对应证据。

正面

已安装文件反查包用 […]；尚不存在的命令反查仓库包用 […]。

背面

已安装文件反查包用 rpm -qf；尚不存在的命令反查仓库包用 dnf provides。

两者查询对象不同。

正面

repo 配置可见性用 […]；真实刷新元数据用 […]。

背面

repo 配置可见性用 dnf repolist --all；真实刷新元数据用 dnf makecache --refresh。

repolist 不充分证明 URL 可达。

正面

当前切换 target 用 systemctl […]；设置启动默认值用 systemctl […]。

背面

当前切换 target 用 systemctl isolate；设置启动默认值用 systemctl set-default。

两者风险与作用时点不同。
