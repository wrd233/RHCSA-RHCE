正面

NetworkManager device 与 connection 的区别是什么？

背面

device 是网卡等设备；connection 是可持久并可激活到设备的配置 profile。

profile 名称不一定等于接口名。

正面

查看设备及其活动 connection 的命令是什么？

背面

nmcli device status

所有 profile 用 nmcli connection show。

正面

只查看已激活 NetworkManager profile，使用什么？

背面

nmcli connection show --active

修改未激活 profile 不会立即改变内核状态。

正面

持久 profile 与当前内核地址分别用什么查询？

背面

nmcli con show <CON> 与 ip -br address。

两组证据可能因尚未激活而不同。

正面

查看内核为特定目的选择的出口、源地址和下一跳，使用什么？

背面

ip route get <DEST>

比只看完整路由表更直接回答路径选择。

正面

ping 网关成功能否证明 DNS 和 TCP 服务正确？

背面

不能；只证明对应路径允许这次 ICMP 交互。

解析、监听和应用协议分别验证。

正面

静态 IPv4 profile 的关键 method 值是什么？

背面

ipv4.method manual

还要设置地址/前缀、网关和 DNS。

正面

创建绑定 enp1s0、名为 exam-static 的以太网 profile 骨架是什么？

背面

nmcli con add type ethernet ifname enp1s0 con-name exam-static ...

继续指定 IPv4 目标状态。

正面

激活 exam-static profile 的命令是什么？

背面

nmcli connection up exam-static

远程操作前必须评估断连风险。

正面

nmcli con mod 修改多值属性时，前缀 + 与 - 表示什么？

背面

追加一个值；删除指定值。

不带前缀通常替换整个属性。

正面

profile 中静态地址正确但 ip -br a 仍是旧地址，优先判断什么？

背面

新 profile 尚未激活到设备，或另一 profile 仍在活动。

查看 nmcli con show --active。

正面

静态网络配置的最小验收层次是什么？

背面

profile 属性 → 当前地址 → 路由 → DNS → 必要连通功能。

autoconnect 另证持久性。

正面

设置静态主机名的命令骨架是什么？

背面

hostnamectl set-hostname <FQDN>

不会自动发布 DNS 记录。

正面

/etc/hosts 条目的典型字段顺序是什么？

背面

IP 地址、规范主机名、可选别名。

写入前检查同名或同地址冲突。

正面

验证应用常用的系统名称解析入口，首选什么？

背面

getent hosts <NAME>

它按 NSS 配置工作，可包含 hosts 与 DNS。

正面

dig 成功与 getent hosts 成功证明的是同一件事吗？

背面

不是；dig 直接查 DNS，getent 走系统 NSS 解析路径。

/etc/hosts 可影响后者而不影响前者。

正面

SSH 密钥对中，哪一部分可以安装到远端？

背面

公钥 .pub；私钥保留在客户端并严格保护。

不向远端复制私钥。

正面

生成 ed25519 密钥对的命令骨架是什么？

背面

ssh-keygen -t ed25519 -f <PRIVATE_KEY_PATH>

会同时生成对应 .pub 文件。

正面

把指定公钥安装到远端 alice 账号的命令骨架是什么？

背面

ssh-copy-id -i <KEY>.pub alice@<HOST>

通常需要一次已有认证。

正面

修改 sshd 配置后，重载前必须运行什么？

背面

sshd -t

在密钥验证前不要关闭现有认证路径。

正面

SSH 公钥认证失败的双端证据入口是什么？

背面

客户端 ssh -v，服务端 journalctl -u sshd。

再查用户、路径权限和 SELinux 标签。

正面

known_hosts 报主机密钥变化时，应先做什么？

背面

通过可信渠道核对服务端指纹。

确认合法变化后才用 ssh-keygen -R 移除旧记录。

正面

SSH 登录成功后，如何证明实际远端身份与主机？

背面

在远端运行 id 与 hostname。

连接退出 0 仍需确认目标对象。

正面

查看 firewalld 当前活动 zone 与接口归属，使用什么？

背面

firewall-cmd --get-active-zones

规则必须添加到实际处理流量的 zone。

正面

firewalld service 与 port 规则的区别是什么？

背面

service 是命名的端口/协议集合；port 直接写 PORT/PROTOCOL。

有准确 service 定义时优先使用。

正面

当前立即允许 public zone 的 HTTP，命令是什么？

背面

firewall-cmd --zone=public --add-service=http

这是 runtime 修改。

正面

持久允许 public zone 的 TCP 8080，命令是什么？

背面

firewall-cmd --zone=public --add-port=8080/tcp --permanent

不立即改变 runtime。

正面

不带与带 --permanent 的 firewalld 修改分别作用哪里？

背面

runtime 当前规则；持久配置。

两层都要分别查询。

正面

firewall-cmd --reload 对 runtime 有什么影响？

背面

用持久配置重建 runtime，未持久的运行时变化会丢失。

reload 前先理解其他 runtime-only 规则。

正面

分别查询 public zone HTTP 的 runtime 与 permanent 状态，使用什么？

背面

--query-service=http，持久查询再加 --permanent。

两条查询都应显式指定 zone。

正面

防火墙已允许 80/tcp，能否证明 httpd 正在监听？

背面

不能；防火墙只允许流量，不创建监听。

使用 ss -lntp 和协议请求验证。

正面

数字 IP 可达但主机名失败，优先检查哪一层？

背面

系统名称解析层：NSS、DNS server/search 和 hosts 冲突。

不应继续改地址或路由。

正面

服务 active 但远端访问失败的证据推进骨架是什么？

背面

监听 → 本机协议请求 → zone/runtime/permanent → 远端请求 → SELinux。

拒绝与超时只是线索，不是绝对根因。

正面

静态网络、SSH、HTTP 综合任务的验收骨架是什么？

背面

profile/当前网络/DNS → SSH 远端身份 → 服务状态/监听 → 正确 zone 双态 → 外部 HTTP。

每层单独取证。

正面

NetworkManager 的 […] 是设备，[…] 是可持久激活的配置 profile。

背面

NetworkManager 的 device 是设备，connection 是可持久激活的配置 profile。

名称不必相同。

正面

firewalld 不带 --permanent 修改[…]；带该参数修改[…]。

背面

firewalld 不带 --permanent 修改runtime；带该参数修改持久配置。

reload 用持久配置重建 runtime。

正面

SSH 密钥认证：客户端保留[…]，远端 authorized_keys 保存[…]。

背面

SSH 密钥认证：客户端保留私钥，远端 authorized_keys 保存公钥。

私钥不得分发。
