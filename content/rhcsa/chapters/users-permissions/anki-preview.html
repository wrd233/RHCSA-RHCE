用户、组、权限、ACL 与 sudo - Anki 预览

共 36 条有效 Note；本页面不显示来源、稳定 ID 与标签。

正面

/etc/passwd、/etc/shadow、/etc/group 分别保存什么核心信息？

背面

账号属性；口令哈希与期限；组定义与显式成员。

用户主组由 passwd 中的主 GID 表达。

正面

为什么 /etc/group 某组成员列表为空仍可能有人属于该组？

背面

用户可以通过 /etc/passwd 中的主 GID 把该组作为主组。

使用 id <USER> 汇总身份。

正面

通过系统名称服务查询账号和组，推荐什么命令？

背面

getent passwd <USER> 与 getent group <GROUP>。

比直接 grep 本地文件更符合解析语义。

正面

useradd -u、-g、-G、-s 分别指定什么？

背面

UID、主组、附加组列表、登录 Shell。

-d 指定家目录，-m 创建家目录。

正面

给 alice 追加附加组 developers 的正确命令是什么？

背面

usermod -aG developers alice

漏掉 -a 会替换附加组列表。

正面

管理员已把用户加入新组，但其当前 Shell 的 id 看不到，原因是什么？

背面

进程在启动时取得附加组，现有会话未刷新。

重新登录或创建新的组身份会话。

正面

目录的 r、w、x 分别控制什么？

背面

列出名称；创建/删除/改名目录项；穿越并访问已知名称。

与普通文件 rwx 语义不同。

正面

删除一个文件主要取决于文件自身写权限还是父目录权限？

背面

父目录的写和执行权限。

sticky 位可能继续限制删除者身份。

正面

用户既是文件所有者又属于文件组时，权限会相加吗？

背面

不会；匹配 owner 后只使用 owner 权限类。

owner、group、other 三类只选择一类。

正面

umask 为 0027 时，典型新文件和新目录模式是什么？

背面

文件 0640，目录 0750。

程序可请求更窄权限。

正面

只在当前 Shell 执行 umask 0027 能否证明持久策略已配置？

背面

不能；它只影响当前 Shell 及其后代。

持久配置后要用新登录会话创建样本验证。

正面

目录 setgid 位解决什么问题？

背面

让新建对象继承目录所属组。

它不自动保证组写权限。

正面

把 /srv/project 配为组内 rwx 且新对象继承组，模式命令是什么？

背面

chmod 2770 /srv/project

前导 2 是 setgid。

正面

目录 sticky 位的核心效果是什么？

背面

在可写目录中限制删除/改名，通常只允许文件所有者、目录所有者或 root。

典型公共目录模式为 1777。

正面

setgid 协作目录中，新文件仍不允许组写，优先检查什么？

背面

创建进程的 umask 或目录默认 ACL。

setgid 只负责所属组继承。

正面

怎样用 bob 的实际身份测试其能否追加项目文件？

背面

sudo -u bob sh -c 'echo test >> /srv/project/file'

真实功能测试能同时暴露身份、路径和文件权限问题。

正面

访问 ACL 与目录默认 ACL 的核心区别是什么？

背面

访问 ACL 控制当前对象；默认 ACL 作为新建后代的继承模板。

默认 ACL 不回溯修改已有对象。

正面

给 alice 增加当前对象 rw ACL 的命令骨架是什么？

背面

setfacl -m u:alice:rw <PATH>

目录穿越通常需要 x。

正面

给目录设置 alice 的默认 rwx ACL，命令骨架是什么？

背面

setfacl -m d:u:alice:rwx <DIR>

仍应创建新对象检查继承结果。

正面

getfacl 中出现 #effective:r-- 表示什么？

背面

条目写得更宽，但 ACL mask 把有效权限限制为只读。

mask 影响 group class 的多个条目。

正面

为什么不应无条件把 ACL mask 设为 rwx？

背面

它会同时放宽 named users、named groups 和所属组的有效权限上限。

应按目标授权最小调整。

正面

怎样证明默认 ACL 真正影响了新对象？

背面

以目标创建身份新建对象，再对新对象运行 getfacl 和功能测试。

只看目录默认条目不够。

正面

chage -M、-m、-W、-E 分别设置什么？

背面

最大期限、最小期限、到期前警告天数、账号过期日期。

-d 0 常用于强制下次登录修改口令。

正面

查看用户口令期限和口令状态分别用什么？

背面

chage -l <USER> 与 passwd -S <USER>。

两者观察维度不同。

正面

passwd -l 能否保证用户无法通过 SSH 公钥登录？

背面

不能；它锁定口令认证，不必然禁用其他认证方式。

先明确题目要求禁止的访问类型。

正面

/sbin/nologin 的主要作用边界是什么？

背面

阻止正常交互登录 Shell；不能笼统等同于完全禁用账号。

服务账号仍可能运行进程。

正面

校验 sudoers 片段语法的命令骨架是什么？

背面

visudo -cf /etc/sudoers.d/<FILE>

片段权限通常应为 0440。

正面

查看 alice 可用 sudo 授权的命令是什么？

背面

sudo -l -U alice

授权列表正确仍要实际验证目标命令。

正面

sudoers 中 NOPASSWD: 改变什么，不改变什么？

背面

改变是否再次询问口令；不改变允许执行的命令范围。

仍需最小命令授权。

正面

为什么 sudoers 命令通常写绝对路径？

背面

明确授权的是哪个可执行文件，减少 PATH 解析歧义。

仍需检查参数和用户可修改脚本带来的扩权。

正面

Permission denied 的推荐分层调查顺序是什么？

背面

当前 id → 父路径 namei -l → 模式/身份 stat → ACL/mask getfacl → 其他安全层。

最终以目标身份重试功能。

正面

团队协作目录的关键配置骨架是什么？

背面

创建组与成员 → 目录属组 → setgid 模式 → umask/默认 ACL → 多身份验证。

每层解决不同问题。

正面

只允许项目组查看和重启 httpd，sudoers 应避免什么宽泛规则？

背面

避免 %project ALL=(ALL) ALL；只列出所需绝对命令路径。

还要用 visudo 和允许/拒绝测试验收。

正面

usermod […] developers alice 中，-a 表示[…]。

背面

usermod -aG developers alice 中，-a 表示追加而非替换附加组。

修改组后要刷新用户会话。

正面

协作目录 setgid 模式常写 […]；公共可写且防互删目录常写 […]。

背面

协作目录 setgid 模式常写 2770；公共可写且防互删目录常写 1777。

2=setgid，1=sticky。

正面

访问 ACL：setfacl -m […] <PATH>；默认 ACL 增加前缀 […]。

背面

访问 ACL：setfacl -m u:alice:rw <PATH>；默认 ACL 增加前缀 d:。

默认 ACL 只影响新对象。
