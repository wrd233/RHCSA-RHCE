启动过程、Target 与系统恢复 - Anki 预览

共 14 条有效 Note；本页面不显示来源、稳定 ID 与标签。

正面

RHEL 启动主链路是什么？

背面

firmware → boot loader → kernel/initramfs → systemd/target。

失败证据按阶段不同。

正面

查询和设置默认 target 分别用什么？

背面

systemctl get-default；systemctl set-default <TARGET>。

设置只影响下次启动。

正面

systemctl isolate 的作用和风险是什么？

背面

当前切换 target 并停止无关 units，可能中断会话。

不等于 set-default。

正面

rd.break 后真实根通常在哪里？

背面

/sysroot。

先确认并重挂 rw。

正面

重挂真实根为读写的命令是什么？

背面

mount -o remount,rw /sysroot

随后 chroot。

正面

为什么必须 chroot /sysroot 后再 passwd？

背面

否则可能修改 initramfs 环境而非真实系统。

命令成功也可能作用对象错误。

正面

重置口令后创建 /.autorelabel 的目的是什么？

背面

让下次启动对真实文件系统重新进行 SELinux 标记。

relabel 可能耗时。

正面

修复 fstab 的证据顺序是什么？

背面

失败 unit/journal → blkid/lsblk → 编辑 → findmnt --verify → mount -a。

不先重启。

正面

fstab 必需挂载失败时能否默认加 nofail？

背面

不能；这改变要求并掩盖错误。

修正真实 UUID/类型/选项。

正面

查看本次启动错误与失败 units 用什么？

背面

journalctl -b -p err；systemctl --failed。

再进入具体 unit。

正面

passwd 显示成功但重启后旧口令仍有效，优先检查什么？

背面

是否 chroot 到真实根、根是否 rw。

对象层错误。

正面

默认 target 正确能否证明所有服务已运行？

背面

不能；仍需查具体 unit active/enabled 与日志。

target 是依赖集合。

正面

rescue 与 emergency 的大致区别是什么？

背面

rescue 环境较完整；emergency 更小且挂载更少。

按可用工具和题目选择。

正面

root 口令恢复的完整骨架是什么？

背面

rd.break → remount rw → chroot → passwd → autorelabel → exit。

启动后再验收。
