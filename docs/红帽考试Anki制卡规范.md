# 红帽 RHCSA / RHCE Anki 制卡规范

## 1. Anki 的定位

Anki 用于把已经理解的系统知识和操作能力变成能够快速提取的记忆。它不负责第一次讲懂复杂机制，也不代替终端操作。

这套牌组的重点不是背诵大段概念，而是形成一种更“极客”的、面向实际命令和系统状态的记忆：

```text
任务目的 → 选择命令或模块
命令 → 理解作用对象
参数 → 理解目标值、增量值和范围
输出 → 判断当前状态
故障现象 → 选择下一条证据
操作完成 → 选择正确验证
```

Anki 应覆盖讲义中所有具有独立考试价值的知识、操作、验证和诊断点，并额外覆盖讲义中不适合展开、但值得背诵的命令、典型参数、常见组合和任务变式。

覆盖率优先于刻意压缩卡片数量，但不得用机械改写制造重复卡。

---

## 2. “极客卡片”与“文科式卡片”的边界

### 2.1 优先制卡的内容

优先创建以下卡片：

- 从操作目标提取命令骨架；
- 从命令提取作用对象和系统语义；
- 典型参数及其选择条件；
- 大小写、加号、百分比等容易改变命令含义的细节；
- 高频命令组合；
- 配置文件路径和关键字段；
- 典型输出中的判断字段；
- 当前状态与持久状态的区别；
- 一个状态能证明什么、不能证明什么；
- 典型任务的流程骨架；
- 常见故障的下一条证据；
- 命令缺失时的查询入口；
- RHCE 模块名、字段、变量、Jinja2 和 YAML 结构；
- 幂等性、Handler、条件、循环、错误处理和远端验证。

### 2.2 谨慎制卡的内容

概念卡只有在能够帮助以下行为时才值得保留：

- 选择正确命令；
- 判断输出；
- 区分相似对象；
- 推导任务步骤；
- 诊断失败层次；
- 理解参数为什么这样写。

不应大量创建：

- 长篇定义；
- 泛泛的历史背景；
- “请解释某概念”的开放性作文题；
- 只需要重新阅读讲义才能回答的卡；
- 没有明确对错边界的考试心得；
- 纯粹为了覆盖段落而制作的概括卡；
- 已能从另一张卡自然推出、没有独立提取价值的结论。

例如：

不推荐：

```text
题面：请全面介绍 LVM。
答案：一大段 PV、VG、LV、PE、LE、文件系统和挂载的说明。
```

推荐：

```text
题面：`lvs` 已显示 LV 增长，但 `df -hT` 容量没有变化，优先判断哪一层未完成？
答案：文件系统层未扩展。
```

## 3. 覆盖原则

### 3.1 讲义覆盖

讲义中每一个具有独立考试价值的：

```text
知识关系
操作点
参数点
验证点
诊断点
经典任务关键步骤
```

至少应有一种可主动提取的 Anki 表达。

不是逐句转卡。过渡句、场景叙述、修辞性重复和没有独立提取价值的解释不制卡。

### 3.2 讲义外补充

Anki 可以比讲义更深入地覆盖命令和任务，例如：

- `pvs`、`vgs`、`lvs` 的典型 `-o` 字段组合；
- `lvcreate -l`、`-L`、`100%FREE` 的差异；
- `lvextend -l +N -r` 的常用组合；
- `findmnt --verify`、`mount -a`、`findmnt <目录>` 各自证明什么；
- `semanage fcontext -a/-m/-d` 的典型语义；
- Ansible 模块字段、返回值和高频搭配；
- 课程中出现但不值得打断讲义主线的精确路径和参数。

讲义外卡片使用 `coverage::extra` 标签。它们仍必须有可靠来源和明确记忆价值。

### 3.3 多角度覆盖

高价值知识可以从不同提取方向分别制卡：

```text
目的 → 命令
命令 → 作用
参数 → 语义
输出 → 判断
现象 → 下一步
任务 → 流程
错误写法 → 风险边界
```

这些不属于重复，因为它们训练不同路径。

不得机械生成正反卡。只有反向提取具有独立价值时，才创建另一张独立卡和独立 ID。

## 4. Note Type 与字段

只保留两种 Note Type：

```text
RedHat-QA
RedHat-Cloze
```

### 4.1 YAML 源文件

每章维护一个简洁 YAML 文件。推荐结构：

```yaml
chapter_id: RHCSA-LVM
deck: RedHat::RHCSA-RHEL9
note_types:
  - RedHat-QA
  - RedHat-Cloze

notes:
  - id: RHCSA-LVM-O01-QA-001
    type: qa
    question: >-
      查看 VG 的 PE 大小和空闲 extent 数量，推荐什么命令？
    answer: |-
      ```bash
      vgs <VG> -o vg_name,vg_free,vg_extent_size,vg_free_count
      ```
    extra: >-
      extent 题优先查看 `vg_free_count`。
    source:
      - RH134
    tags:
      - exam::rhcsa
      - chapter::lvm
      - card::command
      - priority::P0
```

字段保持固定和扁平：

```text
id
type
question / answer
或 text
extra
source
tags
disabled（可选）
```

不建立数据库，不引入复杂审核状态、记忆理由对象或多级生命周期。

### 4.2 受限 Markdown

字段内部允许：

- 普通段落；
- 行内代码；
- 代码块；
- 少量加粗；
- 简短列表；
- 必要的引用。

不允许：

- 多级标题；
- 复杂表格；
- 任意 HTML；
- 自定义样式；
- 脚本；
- 长篇排版结构。

构建时统一转换为经过清理的 HTML。

## 5. 卡片结构

### 5.1 正面

正面只显示：

- 最小充分上下文；
- 一个明确提取目标；
- 必要的代码、输出或场景片段。

正面不显示：

- 章节；
- 专题；
- 卡片类型；
- 优先级；
- 来源；
- “这是一张诊断卡”等解题提示。

不合格：

```text
如何验证？
```

合格：

```text
`lvs` 已显示 LV 增长，但 `df -hT /srv/project` 仍显示旧容量。优先判断哪一层未完成？
```

### 5.2 背面

背面默认不重复题面，也不显示章节、来源、标签和稳定 ID。

只显示：

```text
最低合格答案

必要的简短补充
```

答案必须：

- 足够精炼；
- 一眼可判断对错；
- 可读性高；
- 重点可少量突出；
- 不整段加粗；
- 不堆叠图标、徽标和信息块。

补充说明遵循“解决当前疑问所需的最短解释”：

- 一至三句；
- 或一个短代码块；
- 或三项以内的短列举。

超过一个短段落时，优先拆卡或交回讲义。

## 6. 卡片颗粒度

### 6.1 原子卡为主

一张卡原则上只训练一个主要提取目标：

- 一个命令骨架；
- 一个参数语义；
- 一个输出判断；
- 一个验证入口；
- 一个诊断下一步；
- 一个相近概念的比较维度。

判断标准不是字数，而是是否存在多个可独立失败的目标。

### 6.2 流程骨架卡

对必须按顺序完成的考试任务，可以制作流程骨架卡：

```text
识别设备
→ 创建 PV
→ 创建 VG
→ 创建 LV
→ 创建文件系统
→ 写入 fstab
→ 验证当前挂载与持久配置
```

流程卡只要求提取阶段和关键依赖，不要求逐字符背诵所有命令。具体命令拆成原子卡。

### 6.3 QA 与 Cloze

- 一个 `qa` 条目生成一张卡；
- 一个 `cloze` 条目通常只有一个编号；
- 最多使用两个紧密相关的 Cloze 编号；
- 不在长命令或整段 Playbook 中挖大量空；
- QA 负责从目标、现象和题干主动提取；
- Cloze 只训练固定结构中的关键精确位置。

### 6.4 输入型卡

只有短、精确、容易拼错的答案适合要求输入：

- 命令名；
- 子命令；
- 模块名；
- 路径；
- 参数；
- 短小 YAML 字段组合。

不要求输入完整 Playbook、长命令序列或开放性解释。

## 7. 命令与操作卡体系

每个重要操作专题应优先考虑以下卡片维度。

### 7.1 对象与查询

训练“要回答这个问题，应看哪一层”：

```text
查看 VG 余量 → `vgs`
查看 LV 路径 → `lvs ... -o lv_path`
查看挂载源 → `findmnt`
查看文件系统容量 → `df -hT`
```

### 7.2 命令骨架

使用占位符训练可迁移结构：

```text
`vgcreate -s <PE_SIZE> <VG> <PV>`
`lvcreate -l <LE_COUNT> -n <LV> <VG>`
`lvextend -l +<LE_COUNT> -r <VG/LV>`
```

### 7.3 参数语义

重点覆盖会实质改变任务结果的参数：

```text
-l 与 -L
有无 +
100%FREE 与 +100%FREE
-a 与 -m
当前状态与持久状态参数
```

不为每个低频参数单独制卡。

### 7.4 具体任务

使用具体值训练真实语法：

```text
PE 为 16 MiB，创建 50 LE 的 projectlv。
```

但只在具体值能暴露单位、引号、顺序或计算错误时创建实例卡。单纯替换用户名、端口或路径不复制新卡。

### 7.5 命令效果

训练命令能证明或改变什么：

```text
`ls -Z` 只能证明当前标签
`semanage fcontext` 建立持久路径规则
`restorecon` 让当前标签符合规则
```

### 7.6 输出解释

题面只保留稳定、必要的输出片段，不考随机 PID、时间戳或完整长日志。

### 7.7 验证与边界

每个高价值操作至少覆盖：

- 完成后看什么；
- 哪个查询只能证明局部状态；
- 还需要哪一层验证；
- 当前成功是否代表持久成功；
- RHCE 第一次成功是否代表幂等。

### 7.8 帮助入口

对不值得背诵的低频细节，训练如何查询：

```text
`man`
`--help`
`dnf provides`
模块文档
系统中的示例和帮助
```

## 8. 题面与答案写作

### 8.1 最小充分上下文

题面必须脱离讲义后仍能独立作答，但不能复制整个任务。

应明确：

- 操作对象；
- 当前状态；
- 目标状态；
- 要求提取命令、参数、判断、验证还是下一步证据。

### 8.2 推荐答案与等价边界

答案面给一条稳定、推荐的标准路径。

评分按系统语义判断：

- 概念卡：核心判断正确即可；
- 命令骨架卡：关键子命令、对象和参数正确即可；
- 精确路径和模块名：必须准确；
- 流程卡：关键阶段和依赖顺序正确即可；
- 输入型和 Cloze：只用于答案边界明确的内容。

等价写法容易造成误判时，用一句话说明边界，不列出所有变体。

### 8.3 当前值与占位符

- 骨架卡使用 `<VG>`、`<LV>`、`<PORT>` 等占位符；
- 实例卡使用具体值；
- 参数变化只有在改变选项、顺序或判断时才形成新卡；
- 不因把 `alice` 换成 `bob` 而创建另一张卡。

## 9. 标签

普通卡片只强制三个标签：

```text
exam::rhcsa
chapter::lvm
card::command
```

即：

1. 考试归属；
2. 章节归属；
3. 提取类型。

常用提取类型：

```text
card::concept
card::comparison
card::command
card::parameter
card::verification
card::diagnosis
card::output
card::process
card::calculation
card::cloze
card::ansible
```

按需标签：

```text
priority::P0
priority::P1
coverage::extra
topic::file-context
task::custom-web
version::sensitive
origin::mistake
bridge::rhce
```

约束：

- 来源只保存在 `source` 字段；
- 不增加难度、审核状态和记忆理由等低价值标签；
- `coverage::extra` 只给讲义外卡；
- `bridge::rhce` 用于 RHCE 阶段需要回顾的 RHCSA 卡；
- 标签使用固定的小写英文和层级命名。

## 10. RHCSA 与 RHCE 的重叠

系统机制与手工操作只维护一份 RHCSA 卡。

RHCE 另外创建新的自动化提取角度：

```text
系统目标 → Ansible 模块
手工状态 → 模块参数
任务依赖 → Handler
系统输出 → 远端终态验证
第一次执行 → 第二次幂等检查
```

不能把 RHCSA 卡原样复制到 RHCE 牌组。

---

## 11. ID、更新与停用

稳定 ID 代表“主要提取目标”，而不是固定措辞。

保留 ID：

- 修正错别字；
- 精炼题面；
- 精炼答案；
- 修正同一目标下的语法；
- 调整补充说明、来源或标签。

创建新 ID：

- 提取方向发生变化；
- 从概念卡变为诊断卡；
- 从手工操作变为 Ansible 表达；
- 一张宽卡拆成多个独立目标；
- 核心正确答案改变。

卡片退出使用时只增加：

```yaml
disabled: true
```

同步时暂停，不自动永久删除。不建设复杂的归档、废弃和替代状态。

## 12. 覆盖检查

每章生成轻量覆盖摘要，检查：

- 每个知识专题是否有必要卡片；
- 每个操作专题是否覆盖命令、参数和验证；
- 每个诊断专题是否覆盖症状与下一步证据；
- 每个经典任务是否有流程骨架和关键决策卡；
- 是否加入必要的讲义外命令和参数卡；
- 是否存在重复 ID、无效 Cloze 或近似重复。

硬性阻断项：

- P0/P1 操作完全没有覆盖；
- 关键命令或参数卡缺失；
- 经典任务缺少主要流程或验收卡；
- 重复 ID；
- QA 缺少题面或答案；
- Cloze 无效；
- YAML 无法解析；
- 无法确认的高风险内容被写成确定答案；
- 明显重复卡训练同一提取目标。

卡片数量、QA/Cloze 比例和某专题卡片较多只能作为提醒，不阻止交付。覆盖率优先。

## 13. 预览、同步与交付

每章生成：

```text
chapter.yml
chapter-preview.html
chapter-summary.md
```

HTML 按最终 Anki 模板顺序展示正面和答案面，不开发复杂浏览器。

流程：

```text
生成 YAML
→ 自动检查
→ 生成 HTML 预览与覆盖摘要
→ 用户查看
→ 用户明确要求同步
→ Codex 通过 AnkiConnect 更新 Anki
```

不得在生成完成后自动同步。

AnkiConnect 是日常增量更新的主要方式：

- 按稳定 ID 新增或更新；
- 同步标签和媒体；
- `disabled: true` 时暂停；
- 不从 Anki 反向覆盖 YAML；
- 不自动修改复习调度。

`.apkg` 只在 RHCSA、RHCE 或整套卡片阶段性完成时生成，用于备份和迁移。

---

## 14. Anki 视觉规范

所有卡片共用一套克制模板。

正面：

```text
题面
必要的命令、输出或代码
```

背面：

```text
最低合格答案

必要补充
```

规则：

- 背面不重复题面；
- 不显示章节、来源、ID 和标签；
- 不显示卡片类型徽标；
- 不使用大量彩色框；
- 命令、路径和参数使用等宽字体；
- 代码块保持真实缩进；
- 深蓝色仅用于极少量边框或强调；
- 兼容浅色与深色；
- 答案始终优先占据视觉中心。

图片只用于不可替代的界面识别和结构关系。命令、YAML、日志和输出不得做成图片。

## 15. 制卡自检清单

### 内容

- 这张卡是否帮助操作、判断、验证或排错？
- 是否过于“文科式”，要求背一段定义？
- 是否有一个明确提取目标？
- 是否值得独立调度？
- 是否只是另一张卡的措辞改写？

### 命令

- 命令作用对象是否明确？
- 关键参数是否具有真实考试价值？
- 是否覆盖了典型组合？
- 是否说明了命令能证明什么、不能证明什么？
- 低频细节是否更适合做查询入口卡？

### 题面

- 脱离讲义后能否独立作答？
- 是否泄露章节和解题方向？
- 是否包含确定唯一答案所需的最小上下文？
- 是否把多个任务塞进一张卡？

### 答案

- 最低合格答案是否一眼可见？
- 是否足够精炼、清晰、可读？
- 补充说明是否只解决当前疑问？
- 是否存在大段加粗或长篇解释？
- 是否把推荐路径和所有变体混在一起？

### 维护

- ID 是否稳定且唯一？
- 标签是否只保留必要维度？
- 讲义外卡是否标记 `coverage::extra`？
- 是否通过覆盖与格式检查？
- 是否在用户确认前保持未同步状态？
